**ECMA-119 spec text (checked 2026-10-22):** Ecma International, *ECMA-119, 5th edition (December 2024)*, Table 8 (p. 37) assigns BP 27 to File unit size and BP 28 to Interleave gap size; §§10.1.8–10.1.9 (p. 40) define both as 8-bit fields that are zero unless the file section is recorded in interleaved mode. Because BP numbering starts at 1, the zero-based record indexes are 26 and 27, matching `rec[26]` and `rec[27]`. The inspector rejects either non-zero value with `INTERLEAVED_UNSUPPORTED`; targeted synthetic tests cover each byte independently and verify that input bytes are unchanged. Interleaved layouts remain unsupported.

**ECMA-119 volume-space text (checked 2026-10-22):** *ECMA-119, 5th edition (December 2024)*, §9.4.9 (p. 26) defines Volume space size (BP 81 to 88) as a 32-bit number of logical blocks in which the volume space of the volume is recorded. The inspector reads this field in both-endian form, rejects an image smaller than the declaration, and bounds directory and file reads to the declared volume. An image larger than the declared volume is accepted; bytes beyond it are not treated as ISO 9660 content. This standard text does not explain layered PS2 media or the meaning of such extra bytes.

**ORI synthetic model (recorded 2026-10-23):** `tests/test_instruction_ori.py` defines and tests a narrow 32-bit zero-extending `ORI` model for opcode `0x0D`, including zero-register handling, through an independent synthetic program and a generated-C++ differential. This is an RPTP test definition and not a claim of complete R5900 semantics or a hardware specification. The accepted Gate 0 fixture and its SHA-256 are unchanged; see [INSTRUCTION_CATALOG.md](INSTRUCTION_CATALOG.md).

**ANDI/XORI synthetic model (recorded 2026-10-23):** `tests/test_instruction_logical.py` defines and tests narrow 32-bit zero-extending logical-immediate models for `ANDI` opcode `0x0C` and `XORI` opcode `0x0E`. The tests cover masking, toggling, zero-extension, `$zero` writes, source/destination overlap, boundary values, composition with existing operations, deterministic lowering and native differential behavior. This is an RPTP test definition and not a claim of complete R5900 semantics or a hardware specification. The accepted Gate 0 and ORI fixtures are unchanged; see [INSTRUCTION_CATALOG.md](INSTRUCTION_CATALOG.md).

**LUI synthetic model (recorded 2026-10-23):** `tests/test_instruction_lui.py` defines and tests a narrow `LUI` model for opcode `0x0F`: `rs` must be zero, the raw 16-bit immediate is shifted left 16 bits, and the 32-bit result is sign-extended into the 64-bit register array. The tests cover all boundary values, `$zero`, reject nonzero `rs`, IR metadata, deterministic lowering, malformed metadata and native differential behavior. The semantics are cross-checked against `RPTP-REF-013`, Revision 5.04 page 225; the Revision 6.03 page itself was not accessible. This remains an RPTP synthetic test definition, not a claim of complete R5900 semantics or a hardware specification. The accepted Gate 0, ORI and ANDI/XORI fixtures are unchanged; see [INSTRUCTION_CATALOG.md](INSTRUCTION_CATALOG.md).

**Register-logical synthetic model (recorded 2026-10-23):** `tests/test_instruction_register_logic.py` defines and tests narrow `AND` (`SPECIAL` funct `0x24`), `OR` (`0x25`) and `XOR` (`0x26`) models with `shamt=0`. The tests cover full modeled 64-bit bitwise results, upper-bit patterns, all-zero/all-one values, `$zero`, source/destination aliasing, malformed `shamt`, malformed IR, deterministic lowering and native differential behavior. `RPTP-REF-001` and `RPTP-REF-002` support the function codes and bitwise operation names; the 64-bit operation width is an RPTP test definition, not a claim of complete R5900 semantics or a hardware specification. The accepted Gate 0, ORI, ANDI/XORI and LUI fixtures are unchanged; see [INSTRUCTION_CATALOG.md](INSTRUCTION_CATALOG.md).

**NOR synthetic model (recorded 2026-10-24):** `tests/test_instruction_nor.py` defines and tests a narrow `NOR` (`SPECIAL` funct `0x27`) model with `shamt=0`. The tests cover full modeled 64-bit complement-of-union results, upper-bit patterns, all-zero/all-one values, `$zero`, source/destination aliasing in both directions, malformed `shamt`, malformed IR, deterministic lowering and native differential behavior. `RPTP-REF-001` and `RPTP-REF-002` support the function code and bitwise operation name; the 64-bit operation width is an RPTP test definition, not a claim of complete R5900 semantics or a hardware specification. **SLT synthetic model (recorded 2026-10-24):** `tests/test_instruction_slt.py` defines and tests a narrow `SLT` (`SPECIAL` funct `0x2A`) model with `shamt=0`. The tests cover signed two's-complement 64-bit comparison, negative/zero and positive/negative operands, equality, high-bit sign patterns, `$zero`, source/destination aliasing in both directions, malformed `shamt`/IR, deterministic lowering, native differential behavior and a generated-helper boundary check at `INT64_MIN`/`INT64_MAX`. `RPTP-REF-001` and `RPTP-REF-002` support the function code and signed set-on-less-than naming; the 64-bit signed comparison width is an RPTP test definition, not a claim of complete R5900 semantics or a hardware specification. The accepted Gate 0, ORI, ANDI/XORI, LUI, AND/OR/XOR and NOR fixtures are unchanged; see [INSTRUCTION_CATALOG.md](INSTRUCTION_CATALOG.md).

**IR lowering synthetic model (recorded 2026-10-23):** `tools/rptp_lower.py` and `tests/test_ir_lowering.py` define a deterministic C++20 state machine for the same synthetic subset. ## Verification labels

- **Verified by local test:** the synthetic fixture is reproducible; its parser accepts it and rejects selected malformed inputs; generated C++ matches the reference interpreter for the supported fixture path. The recorded runs include Linux/GCC, Linux/Clang and Windows x64/MSVC. Separate synthetic ORI, ANDI/XORI, LUI, register-logical AND/OR/XOR/NOR and SLT programs cover post-Gate-0 increments, and a separate IR-lowering path covers deterministic C++ generation for the same synthetic model.
- **Document-cross-checked:** common MIPS instruction encodings, including the `SLT` function code and name, and generic ELF fields referenced above. The modeled 64-bit signed comparison remains test-defined.
- **Not verified:** complete R5900 semantics, delay-slot details beyond the fixture model, EE-specific floating-point/MMI behavior, VU behavior, GS pixel behavior, IOP services, DMA ordering, hardware timing, ISO inspection/boot and commercial-game compatibility.
