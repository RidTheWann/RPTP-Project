## Context

RPTP currently contains four independently authored decode/execute/emit models. They were built as separate evidence carriers, and no document declares which one is the product path.

| Path | Role today | Supported model at this baseline | Known differences |
|---|---|---|---|
| `tools/rptp_gate0_spike.py` | Self-contained Gate 0 differential spike; accepted narrow synthetic evidence | 28 operations; 64-bit registers; initialized-word memory; no `LW`/`SW` alignment check | No branch forms beyond `BEQ`/`BNE`; not the canonical pipeline |
| `tools/rptp_ir.py` + `tools/rptp_lower.py` | Legacy IR and deterministic C++ lowering | 28 operations; 64-bit registers; initialized-word memory; no `LW`/`SW` alignment check | Rejects the six ordinary branch forms, all eight branch-likely forms and the nine doubleword shifts |
| `tools/rptp/` | Decoder, CFG, host IR, Python oracle and C++ emitter | 142 decoder mnemonics; 51 Level B semantic operations; 128-bit register pairs; 32 MiB default-zero RAM; alignment checks | Not a product runtime; C++ output is a test artifact; analysis language is Python and its long-term role is an open decision |
| `runtime/` | Native C++20 loader and synthetic execution harness | 51 operations; 64-bit registers; mapped ELF regions; alignment checks | Test vehicle only; no kernel, syscall, ISO ingestion or generated-code runtime |

The duplication is deliberate historical evidence, but it creates `R-031`: an instruction tested on one path is not automatically supported or identically behaved on another. The 2026-10-30 `R-032` review found a real branch-lowering defect (a branch targeting address 0 was lowered as the fall-through) and uncovered delay-slot link-ordering coverage gaps, even though the other paths had related behavior. The inventory in [research/instruction-semantics-matrix.md](../research/instruction-semantics-matrix.md) §5 records the asymmetries.

[AGENTS.md](../../AGENTS.md) fixes the product architecture as ahead-of-time recompilation to C++ plus a from-scratch native runtime, and defines the Python interpreter as a test oracle only. That does not select among the Python analysis pipelines, and it does not authorize deleting the legacy paths. The owner has not declared a canonical path; `R-031` stays open.

## Decision (proposed)

1. **Canonical front end.** The `tools/rptp/` package is the only path for new R5900 decoding, CFG, host IR, reference-oracle and C++ emission behavior. A new instruction or semantic rule lands there with its tests, approved reference and evidence record before any other path may claim it.
2. **Canonical native target.** The `runtime/` C++20 library and its `rptp-load`/`rptp-run` tools are the only native execution model for new behavior. C++ generated by `tools/rptp/codegen.py` remains a differential test artifact until a separate product loader/runtime design exists; neither is the product today.
3. **Legacy freeze.** `tools/rptp_gate0_spike.py`, `tools/rptp_ir.py` and `tools/rptp_lower.py` are frozen evidence surfaces. They receive no new instructions, no new semantic rules and no silent redirection to the canonical path. Only test-harness, documentation and provenance fixes that do not change their modeled behavior may land, and those must name the affected paths and prove the behavior is unchanged.
4. **No deletion before equivalence.** No legacy path is deleted, rewritten or demoted before the gates below pass on one recorded commit and the owner accepts an update to this ADR. Until then, the legacy paths remain available as historical differential evidence.
5. **New behavior never expands the legacy subset.** Branch-likely forms, the six ordinary branch forms and the nine doubleword shifts remain canonical-only unless a future owner decision reopens the legacy scope. The freeze in item 3 applies even if the canonical path later supports them.
6. **Analysis-language and product boundaries stay open.** This ADR does not decide whether the inspector or analyzer remains Python or moves to C++, does not define a product kernel or runtime, and does not authorize extraction or game execution. Those need separate ADRs.
7. **No status change.** Accepting this ADR would declare a canonical engineering direction, not pass Gate 3, certify a component or claim game compatibility. Gate 0 remains a narrow technical pass; Gate 2 remains open and read-only; Gate 3 remains not passed.

## Equivalence gates before legacy retirement

| ID | Gate | Required evidence | Status on 2026-10-31 |
|---|---|---|---|
| E1 | Inventory and containment | A test proves the frozen legacy lowering set, its containment in the canonical decoder and the canonical-only branch forms | Verified by [tests/test_path_contract.py](../../tests/test_path_contract.py) (`PathInventoryTests`) locally and on hosted CI at `88143ad` (runs `41008377188`, `41008382350`) |
| E2 | Shared-subset semantic equivalence | One synthetic program containing every legacy operation produces identical low-64 register state, halt PC and executed-PC trace in the legacy oracle and the canonical oracle; both analyzers and the legacy lowerer accept the program | Verified by the same test (`SharedSubsetEquivalenceTests`) locally and on hosted CI at `88143ad`; this covers the two Python oracles, not native code |
| E3 | Native equivalence | The shared legacy subset is compared through the legacy generated C++, the canonical generated C++ and the `rptp-run` harness on the same synthetic input, with documented memory-model normalization | Covered for the shared 28-operation program by [tests/test_native_legacy_equivalence.py](../../tests/test_native_legacy_equivalence.py): the legacy generated C++, the canonical oracle, the canonical generated C++ and `rptp-run` agree on low-64 registers, `$zero`, memory-write bytes, final PC, executed-PC trace, step count and halt state after word writes are expanded to little-endian bytes. Local evidence 2026-10-31 on Windows x64/MSVC; exact-head push and pull-request runs `41135236148`/`41135242328` and merge-commit run `41135564739` passed both jobs, recorded in [VERIFICATION_LOG.md](../VERIFICATION_LOG.md). One program is not full gate sign-off by itself, and E4 remains open |
| E4 | Fail-closed parity | Rejection classes for unsupported encodings, missing or control delay slots, unaligned `LW`/`SW`/`LD`/`SD`, unmapped or cross-region access and link `rs = 31` are mapped and tested across the surviving paths | Open: the legacy paths have no alignment check and use different error surfaces; identical messages are not required, equivalent rejection is. Partial progress 2026-10-31: the canonical decoder now rejects a nonzero reserved `shamt` on the variable doubleword shifts fail-closed, matching the native harness (`tests/test_isa_encodings.py`, `tests/test_instruction_dshift.py`, `tests/test_runtime_execution.py`); two delay-slot classes (missing delay slot, control transfer in a delay slot) now fail closed across the canonical CFG/oracle, the frozen legacy IR and the native harness in `tests/test_fail_closed_parity.py`; the remaining failure classes still keep this gate open |
| E5 | Per-increment provenance | Each behavior change names its reference IDs, independent test path, fail-closed policy and evidence in the commit body and [VERIFICATION_LOG.md](../VERIFICATION_LOG.md) | Ongoing under [PROVENANCE_PLAN.md](../PROVENANCE_PLAN.md) |

Retirement means deleting, rewriting or making a legacy path non-executable. It requires E1–E4 green on a recorded commit, a migration note naming the replaced tests, and an owner-accepted update to this ADR. Passing local tests or a single synthetic program does not satisfy E3 or E4 by itself.

## Consequences if accepted

- Future instruction increments target `tools/rptp/` and the native harness; adding an instruction to the legacy paths is out of policy.
- The legacy paths remain runnable and their tests remain in the suite until E1–E4 and owner acceptance, so historical Gate 0 evidence stays reproducible.
- `R-031` can be closed only when the owner accepts this ADR; the executable E1/E2 guard then prevents silent drift while E3/E4 are built.
- The instruction-semantics matrix remains the factual inventory; it must be updated when a gate status changes.
- A future owner choice of a different canonical path supersedes this ADR and requires updating the guard test and the evidence matrix together.

## Re-evaluation criteria

Revisit this ADR when the owner accepts or rejects it, when a new execution or emission path is proposed, before the first product vertical slice, or when any party requests retirement of a legacy path. Only the owner may change this ADR to Accepted or supersede it.
