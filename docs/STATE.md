## Scope and blockers

The Gate 0 disposition covers a synthetic ELF32/EM_MIPS fixture and only ADDIU, ADDU, LW, SW, BEQ, BNE, J, JAL, JR and NOP, including tested delay-slot behavior. The separate `ORI`, `ANDI`, `XORI`, `LUI`, `AND`, `OR`, `XOR`, `NOR` and `SLT` differentials are post-disposition Gate 3 work and are **not** part of the accepted Gate 0 scope. The IR/CFG analysis, known-edge graph reachability and deterministic lowering are also post-disposition Gate 3 work, cover only the same synthetic code model, and make no runtime-reachability, dead-code-proof, function-extent or product-runtime claim. None of these results establishes complete R5900 semantics, retail ISO compatibility, booting a commercial game, or implementation of PS2 kernel services, VU, GS, IOP, CDVD, audio, controller, memory card, timing or save-state behavior.

1. **Provenance reviews:** the Gate 0 spike and ISO inspector have recorded neutral references and tests but remain `Provisional independent`; the build/CI/doctor layer remains `Review required`. Independent review is required before Gate 2 closure where applicable and before product release.
2. **Clean-room/source exposure (policy resolved):** prior technical exposure is documented in REFERENCES.md and ADR-0001. The owner selected the ADR-0003 sealed-source policy on 2026-10-21: sealed projects must not be accessed, and affected work must be independently derived with provenance and tests. The historical exposure cannot be erased; this policy reduces future contamination but is not a legal guarantee.
3. **License confirmation (resolved):** the owner confirmed GPL-3.0-or-later on 2026-10-21; SPDX headers were added to covered project source, build and workflow files.
4. **Gate 2 (open):** multi-extent/ISO-variant review remains open. Gate 2 is read-only; extraction is deferred and requires a separate ADR and threat model.
5. **Renderer:** no renderer has been selected or tested; ADR-0002 remains a plan.
6. **Dependencies:** no new runtime dependency was introduced by the repository/toolchain baseline. Continue to record license, version and required notices before adding or vendoring dependencies.
