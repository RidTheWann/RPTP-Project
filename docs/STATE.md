It covers only the synthetic ELF32/EM_MIPS fixture and its tested subset; it is not a clean-room certification, independent review, runtime, boot or compatibility claim. See [GATE0_REVIEW.md](GATE0_REVIEW.md).
2. **Gate 2:** **not passed** and read-only under [ADR-0004](DECISIONS/ADR-0004-gate2-read-only-scope.md); extraction is deferred and needs a separate ADR and threat model. Evidence gaps are mapped in [GATE2_EVIDENCE.md](GATE2_EVIDENCE.md).
3. **Gate 3:** **not passed**. The tested synthetic subset, IR/CFG and lowering are in [INSTRUCTION_CATALOG.md](INSTRUCTION_CATALOG.md) and [IR_CFG.md](IR_CFG.md). `SLTI`, `SLTIU`, `DADDIU` and `SLL` passed earlier runs; `DADDU` (PR #19, `0225916`) and `SUBU` (PR #22, `21fdffc`, run `40849490715`) passed CI, `SUBU` being the latest synthetic addition. No product recompiler, function discovery or real-game code generation exists; the native runtime harness is a separate B2 test vehicle.
4. **Increment traceability:** [INCREMENT_LEDGER.md](INCREMENT_LEDGER.md) records each increment's behavior, references and tests.
5. **ISO inspector and census:** single-volume ISO 9660, strict descriptor/record/config validation, root `SYSTEM.CNF`, BOOT path resolution, ELF PT_LOAD bounds/alignment/order/zero-fill and entry load-map metadata with overlap warnings, SHA-256 metadata, byte budgets, explicit error taxonomy and a metadata-only directory survey exist. The read-only boot-code census (merged via PR #12, `88d7c68`) reports aligned PT_LOAD word counts and current-decoder acceptance for file or ISO input without extraction. Details: [ISO_INSPECTOR.md](ISO_INSPECTOR.md), [BOOT_CENSUS.md](BOOT_CENSUS.md); read-only, fail-closed, no extraction path.
6. **Native runtime foundation:** C++20 `rptp_runtime` provides sparse guest memory, a fail-closed ELF32 little-endian `ET_EXEC`/`EM_MIPS` `PT_LOAD` loader (`rptp-load`, `rptp.runtime.load.v1`, stable `LOAD_*` errors) and a synthetic execution harness (`rptp-run`, `rptp.runtime.run.v1`) for the documented synthetic subset plus one delay slot, with `EXEC_*` errors and a step budget (PR #15 and #17, `ebcc2b0`/`ddc0de5`). CTest covers direct C++ checks and independent Python-built loader/execution CLI differentials. The harness is a test vehicle only: no kernel, syscall, ISO ingestion, boot or compatibility. Contract: [RUNTIME.md](RUNTIME.md).
7. **Provenance:** the Gate 0 spike, ISO inspector and native runtime loader are `Provisional independent`; the build/CI/doctor layer is `Review required` and none is clean-room certified. See [CLEAN_ROOM_AUDIT.md](CLEAN_ROOM_AUDIT.md) and [PROVENANCE_PLAN.md](PROVENANCE_PLAN.md).

Current-decoder acceptance before `SUBU` is 58.3–69.2% of file-backed PT_LOAD words; counts include data and are not function-level. No boot, recompilation, native port or compatibility exists.

## Scope and blockers

The accepted Gate 0 scope is the synthetic ELF32/EM_MIPS fixture and only ADDIU, ADDU, LW, SW, BEQ, BNE, J, JAL, JR and NOP plus tested delay slots. The separate `ORI`, `ANDI`, `XORI`, `LUI`, `AND`, `OR`, `XOR`, `NOR`, `SLT`, `SLTU`, `SLTI`, `SLTIU`, `DADDIU`, `DADDU` and `SUBU` differentials, and the IR/CFG, known-edge reachability and lowering work, are post-disposition Gate 3 work: they make no runtime-reachability, dead-code-proof, function-extent, product-runtime or compatibility claim.

1. **Provenance reviews (open):** independent review of the ISO inspector before Gate 2 closure, and of the Gate 0 and build/CI/doctor components before product release.
2. **Gate 2 (open):** multi-extent and ISO-variant review, plus the owner's Gate 2 disposition. Interleaved layouts are rejected even though the BP 27/28 field mapping is spec-checked.
3. **Clean-room/source exposure (policy resolved):** prior exposure is documented in [REFERENCES.md](REFERENCES.md) and ADR-0001; ADR-0003 seals the affected projects and is not a legal guarantee.
4. **License (resolved):** GPL-3.0-or-later confirmed 2026-10-21; SPDX headers cover project source, build and workflow files.
5. **Renderer (open):** none selected or tested; ADR-0002 remains a plan.
6. **Dependencies:** no runtime dependency is vendored or linked; record license, version and notices before adding one.
