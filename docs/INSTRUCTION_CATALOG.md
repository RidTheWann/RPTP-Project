# RPTP synthetic instruction catalog

- **Status date:** 2026-10-30
- **Scope:** narrow synthetic ELF32/EM_MIPS differential spike, not a complete R5900 implementation and not a compatibility list.
- **Provenance:** [ADR-0003](DECISIONS/ADR-0003-sealed-source-clean-room-policy.md), [PROVENANCE_PLAN.md](PROVENANCE_PLAN.md) and [REFERENCES.md](REFERENCES.md).
- **Gate status:** Gate 3 is not passed. This catalog records what the current synthetic tests actually exercise. A documented IR, candidate-only CFG analysis, conservative known-edge graph reachability and deterministic C++ lowering now exist for the same subset, including the `DADDIU` immediate, the `DADDU` full 64-bit register addition, the `SUBU` 32-bit register subtraction, the `ANDI`, `ORI`, `XORI`, `SLTI` and `SLTIU` immediates, the `LUI` shifted immediate, the `SLL` shift, the `AND`/`OR`/`XOR`/`NOR` register operations, the `SLT` signed comparison, the `SLTU` unsigned comparison and the aligned `LD`/`SD` doubleword pair; see [IR_CFG.md](IR_CFG.md). The `tools/rptp` decoder, host IR, oracle and generated-C++ path also supports the eight branch-likely forms below with architectural delay-slot nullification, cited to `RPTP-REF-015`. Known-edge reachability adds no instruction or runtime behavior.

## Verification levels

- **Native differential:** the decoder, oracle and emitted C++ are exercised by a synthetic program; the generated native state equals the oracle state under a supported host compiler. The Windows/MSVC run is recorded in [VERIFICATION_LOG.md](VERIFICATION_LOG.md).
- **Native IR-lowering differential:** the validated IR is passed to a separate lowering module, the generated C++ state machine is compiled, and its native state equals the oracle state. This proves the synthetic-generated path only. The current tests are in `tests/test_ir_lowering.py`, `tests/test_instruction_logical.py`, `tests/test_instruction_lui.py`, `tests/test_instruction_register_logic.py`, `tests/test_instruction_nor.py`, `tests/test_instruction_slt.py`, `tests/test_instruction_sltu.py`, `tests/test_instruction_slti.py`, `tests/test_instruction_sltiu.py`, `tests/test_instruction_daddiu.py`, `tests/test_instruction_daddu.py`, `tests/test_instruction_sll.py`, `tests/test_instruction_subu.py` and `tests/test_instruction_ld_sd.py`.
- **Static IR/CFG:** the decoder feeds a host-Python IR and fail-closed block analysis. Known-edge graph traversal follows only recorded successors and does not prove native lowering, runtime behavior, dead code or function extents. The current tests are in `tests/test_ir_cfg.py` and `tests/test_cfg_reachability.py`.
- **Decode only:** the decoder recognizes the encoding but no native differential exists. No instruction currently has this status.
- **Unsupported:** the decoder rejects the encoding explicitly. Unsupported instructions are never silently skipped or lowered to an approximation.

## Minimal IR, CFG and lowering coverage

[IR_CFG.md](IR_CFG.md) defines the additional contract for the same subset. It records raw words, normalized operands, explicit signed/zero-extended immediates, `$zero` destination handling, control-flow classes, direct targets, delay-slot ownership, deterministic basic blocks, candidate-only function entries and conservative known-edge graph traversal from an explicit block root. `tools/rptp_lower.py` consumes the validated IR and emits deterministic C++20 for the same synthetic model, with native differential coverage in `tests/test_ir_lowering.py`, `tests/test_instruction_logical.py`, `tests/test_instruction_lui.py`, `tests/test_instruction_register_logic.py`, `tests/test_instruction_nor.py`, `tests/test_instruction_slt.py` and `tests/test_instruction_sltu.py`, `tests/test_instruction_daddiu.py`, `tests/test_instruction_daddu.py`, `tests/test_instruction_sll.py`, `tests/test_instruction_subu.py` and `tests/test_instruction_ld_sd.py`.

The lowering tests cover the supported operations, both branch outcomes, direct and indirect control flow, delay slots, `$zero` writes, 32-bit wraparound, zero-extended logical immediates, signed `SLTI` and unsigned `SLTIU` immediate comparisons, the shifted/sign-extended LUI immediate, full modeled 64-bit register logical operations including NOR, signed 64-bit `SLT` comparison, unsigned 64-bit `SLTU` comparison, the full modeled 64-bit `DADDU` register addition, the 32-bit `SUBU` register subtraction, the 32-bit `SLL` shift, word memory load/store and the aligned `LD`/`SD` doubleword pair. A separate one-instruction fixture covers uninitialized-memory failure. The reachability tests cover only existing stored edges, unresolved indirect transfers and the explicit direct-call continuation caveat. These tests do not add product runtime behavior, runtime reachability, function extents or a complete R5900 model. Gate 3 remains in progress.

The separate `tools/rptp` package (decoder, host IR/CFG, oracle and deterministic C++ emitter) is the path that implements the eight branch-likely forms in this catalog. Its CFG records both the direct target and the fallthrough for every likely branch; nullification is an execution-time effect, not a reachability filter. `tests/test_instruction_branch_likely.py` covers taken and not-taken cases for all eight forms, delay-slot register and memory effects, `$zero`, unconditional link writes, the `rs = 31` rejection, deterministic generated source and a native differential against the oracle. The encodings, PC-relative target, conditions, take-only delay-slot execution and unconditional link write are cited to `RPTP-REF-015` pages 75, 78, 80, 82, 84, 87, 89 and 91; the low-64-bit comparison, 32-bit PC masking, trace/step accounting and fail-closed `rs = 31` rejection are RPTP test definitions. The older `tools/rptp_ir.py`/`tools/rptp_lower.py` pipeline described above remains unchanged and does not implement branch-likely forms.

## Retail boot-code census (read-only, 2026-10-29)

`tools/rptp_census.py` counts aligned 4-byte words in the file-backed `PT_LOAD` ranges of the boot executable inside owner-authorized ISOs and classifies each word with the current synthetic IR decoder. Unsupported words are reported only as raw encoding identifiers (`special_0xNN`, `regimm_0xNN`, `opcode_0xNN`); the tool assigns no instruction names and no semantics. The census reads in memory, writes nothing, has explicit boot-byte and word limits and reuses the inspector's validated ELF parser. It is planning input for Gate 3, not decoder support: no instruction becomes supported by being counted. Results for the eight authorized samples and the report contract are in [BOOT_CENSUS.md](BOOT_CENSUS.md); tests are in `tests/test_boot_census.py`.

## Explicitly unsupported

- All other opcodes, SPECIAL functions, immediate forms and register-field combinations are rejected with an explicit `Unsupported ...` diagnostic.
- The synthetic model does not implement FPU/COP1, MMI, COP0, exceptions, interrupts, TLB, caches, EE kernel services, IOP, DMA, VU, GS, SPU2, CDVD, controllers, memory cards, timers or hardware timing.
- The spike expects ELF32 little-endian `EM_MIPS`, one executable `PT_LOAD` segment and static control-flow targets inside that code model. It does not load retail PS2 executables.
