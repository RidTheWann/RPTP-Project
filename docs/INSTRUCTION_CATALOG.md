# RPTP synthetic instruction catalog

- **Status date:** 2026-10-27
- **Scope:** narrow synthetic ELF32/EM_MIPS differential spike, not a complete R5900 implementation and not a compatibility list.
- **Provenance:** [ADR-0003](DECISIONS/ADR-0003-sealed-source-clean-room-policy.md), [PROVENANCE_PLAN.md](PROVENANCE_PLAN.md) and [REFERENCES.md](REFERENCES.md).
- **Gate status:** Gate 3 is not passed. This catalog records what the current synthetic tests actually exercise. A documented IR, candidate-only CFG analysis, conservative known-edge graph reachability and deterministic C++ lowering now exist for the same subset, including the `ANDI`, `ORI`, `XORI`, `SLTI` and `SLTIU` immediates, the `LUI` shifted immediate, the `AND`/`OR`/`XOR`/`NOR` register operations, the `SLT` signed comparison and the `SLTU` unsigned comparison; see [IR_CFG.md](IR_CFG.md). Known-edge reachability adds no instruction or runtime behavior.

## Verification levels

- **Native differential:** the decoder, oracle and emitted C++ are exercised by a synthetic program; the generated native state equals the oracle state under a supported host compiler. The Windows/MSVC run is recorded in [VERIFICATION_LOG.md](VERIFICATION_LOG.md).
- **Native IR-lowering differential:** the validated IR is passed to a separate lowering module, the generated C++ state machine is compiled, and its native state equals the oracle state. This proves the synthetic-generated path only. The current tests are in `tests/test_ir_lowering.py`, `tests/test_instruction_logical.py`, `tests/test_instruction_lui.py`, `tests/test_instruction_register_logic.py`, `tests/test_instruction_nor.py`, `tests/test_instruction_slt.py`, `tests/test_instruction_sltu.py`, `tests/test_instruction_slti.py` and `tests/test_instruction_sltiu.py`.
- **Static IR/CFG:** the decoder feeds a host-Python IR and fail-closed block analysis. Known-edge graph traversal follows only recorded successors and does not prove native lowering, runtime behavior, dead code or function extents. The current tests are in `tests/test_ir_cfg.py` and `tests/test_cfg_reachability.py`.
- **Decode only:** the decoder recognizes the encoding but no native differential exists. No instruction currently has this status.
- **Unsupported:** the decoder rejects the encoding explicitly. Unsupported instructions are never silently skipped or lowered to an approximation.

## Minimal IR, CFG and lowering coverage

[IR_CFG.md](IR_CFG.md) defines the additional contract for the same subset. It records raw words, normalized operands, explicit signed/zero-extended immediates, `$zero` destination handling, control-flow classes, direct targets, delay-slot ownership, deterministic basic blocks, candidate-only function entries and conservative known-edge graph traversal from an explicit block root. `tools/rptp_lower.py` consumes the validated IR and emits deterministic C++20 for the same synthetic model, with native differential coverage in `tests/test_ir_lowering.py`, `tests/test_instruction_logical.py`, `tests/test_instruction_lui.py`, `tests/test_instruction_register_logic.py`, `tests/test_instruction_nor.py`, `tests/test_instruction_slt.py` and `tests/test_instruction_sltu.py`.

The lowering tests cover the supported operations, both branch outcomes, direct and indirect control flow, delay slots, `$zero` writes, 32-bit wraparound, zero-extended logical immediates, signed `SLTI` and unsigned `SLTIU` immediate comparisons, the shifted/sign-extended LUI immediate, full modeled 64-bit register logical operations including NOR, signed 64-bit `SLT` comparison, unsigned 64-bit `SLTU` comparison and memory load/store. A separate one-instruction fixture covers uninitialized-memory failure. The reachability tests cover only existing stored edges, unresolved indirect transfers and the explicit direct-call continuation caveat. These tests do not add product runtime behavior, runtime reachability, function extents or a complete R5900 model. Gate 3 remains in progress.

## Explicitly unsupported

- All other opcodes, SPECIAL functions, immediate forms and register-field combinations are rejected with an explicit `Unsupported ...` diagnostic.
- The synthetic model does not implement FPU/COP1, MMI, COP0, exceptions, interrupts, TLB, caches, EE kernel services, IOP, DMA, VU, GS, SPU2, CDVD, controllers, memory cards, timers or hardware timing.
- The spike expects ELF32 little-endian `EM_MIPS`, one executable `PT_LOAD` segment and static control-flow targets inside that code model. It does not load retail PS2 executables.

## Verification commands

Through a Visual Studio developer environment for the MSVC path:

```powershell
python -m unittest tests.test_instruction_logical -v
python -m unittest tests.test_instruction_lui -v
python -m unittest tests.test_instruction_register_logic -v
python -m unittest tests.test_instruction_nor -v
python -m unittest tests.test_instruction_slt -v
python -m unittest tests.test_instruction_sltu -v
python -m unittest tests.test_instruction_ori -v
python -m unittest tests.test_ir_cfg -v
python -m unittest tests.test_cfg_reachability -v
python -m unittest tests.test_ir_lowering -v
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-msvc.ps1
```

The separate logical-immediate, LUI, register-logical, NOR, SLT, SLTU and ORI tests use runtime-generated synthetic ELFs and do not modify the registered Gate 0 fixture. The IR/CFG test also builds a synthetic ELF at test time and checks the unchanged Gate 0 and ORI hashes. The reachability tests use synthetic instruction maps and mutate no registered fixture. The lowering tests build separate synthetic ELFs and leave the registered fixture untouched. None of these additions modifies the registered Gate 0 fixture. The IR-lowering path is the only path that compiles generated C++ from the IR; the original spike remains a separate differential path.
